# 实验二迁移记录

原版来源：本机 `Documents/University/2026 Spring/Java/Lab/JavaFX/AircraftWar`。

原版版本：`0a9e09cb29e740e14efd50f6e75abdf569fbe966`，远程仓库 https://github.com/LIAMCHAOS/AircraftWar 。

本次只读取原版，在独立的 AircraftWar2026 工程迁移，不修改原版仓库。

原版实际为 JavaFX 而非 Swing，迁移对应关系为 Pane/AnimationTimer/GraphicsContext/Image/鼠标事件 → SurfaceView/独立线程/Canvas/Bitmap/触屏事件。

## 阶段一：空工程

- 创建原生 Java Activity、Manifest、minSdk 30 和 Gradle 工程。
- 当前本机已安装 SDK 37.0、Build Tools 36.0.0 和 Android Studio 内置 JBR 25。
- 提供标准 Gradle 构建和直接调用已安装 SDK 的离线构建脚本。
- 当前执行环境无法解析外部下载域名，也禁止 ADB 服务绑定本地端口；不将安装启动标记为已通过。

## 阶段二：图片资源

- 从原版复制14张实际素材到 drawable，elitePlus、elitePro、prop_bulletPlus 改为合法的小写下划线名称。
- BitmapFactory 设置 inScaled=false，ImageManager 按 View 缓存；校验解码尺寸与原图一致。
- 原版画布为600×900；Sprite 保存实际图片逻辑尺寸，实体碰撞不依赖 Android Bitmap。
- 用临时普通 View 预览背景和英雄机；阶段三替换为 SurfaceView。

## 阶段三：游戏循环

- MainActivity 默认加载 EasyGame，BaseGame 实现 SurfaceHolder.Callback 和 Runnable。
- 使用单个独立线程、40ms 固定逻辑步长、最多5次补算；背景与英雄机绘制通过 Canvas 完成。
- 使用不可变 Viewport 做600×900逻辑画布的等比缩放；系统栏由根布局统一避让。
- 前台、Surface、尺寸和资源全部准备完成后才能启动；onPause/surfaceDestroyed 等待线程实际退出；恢复时重新计算时间基准。
- 图片不在循环内加载，触摸只发布不可变状态，不直接操作实体集合。

## 阶段四：交互、战斗与验证

| 原版内容 | Android迁移处理 |
| --- | --- |
| AbstractFlyingObject | 保留中心坐标与碰撞公式；尺寸改由纯Java Sprite元数据提供 |
| 飞机、子弹、工厂、射击策略 | 复制原版领域类，替换Main尺寸常量，保留伤害、得分、射击类型和简单模式参数 |
| AbstractGame的tick/碰撞/生成 | 提取为Android无关的GameWorld，由游戏线程调用 |
| JavaFX Image与GraphicsContext | 改为ImageManager的Bitmap缓存和EasyGame的Canvas绘制 |
| 鼠标HeroController | 改为MotionEvent输入快照；游戏线程处理机体命中、偏移和边界 |
| 静态HeroAircraft实例 | 改为每个GameWorld独占一个英雄机，防止Activity重建共享旧状态 |
| 道具Thread.sleep与Platform.runLater | 改为40ms局内时钟递减，不使用道具线程，后台期间效果暂停 |
| 背景音乐、排行榜DAO、菜单和网络 | 按实验二范围暂缓迁移 |

实际修复：

1. 普通子弹命中后退出本轮敌机遍历，避免一弹连续击中多个敌机。
2. 机体碰撞从英雄子弹循环中独立出来，没有子弹时仍然生效。
3. 死亡状态与有效标记共同限制重复伤害、掉落和计分。
4. 炸弹对王牌机按原规则只造成30伤害；仅对实际销毁对象加分。
5. 敌机出生中心和横向反弹考虑完整机体尺寸；完全出界后清理飞机、子弹和道具。
6. 永久冻结不再使用当前时间加Long.MAX_VALUE，消除溢出；临时效果全部由游戏时钟恢复。
7. 触屏与绘制共用同版本视口，取消/暂停/尺寸变化会清除旧输入。
8. 结束画面点击产生新手势后在游戏线程新建世界，无须增加后续实验页面。
